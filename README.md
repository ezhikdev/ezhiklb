# EzhikLB

**EzhikLB (Ezhik Load Balancer)** — панель управления TCP- и UDP-балансировкой на Linux. Панель хранит профили, а агенты на нодах применяют их через IPVS в ядре Linux.

Текущая версия: **0.1.0-beta.3.5 pre-release**.

## Что уже работает

- TCP, UDP или оба протокола в одной записи;
- несколько backend-серверов и распределение по весам;
- планировщики IPVS `wrr` и `rr`;
- Affinity — закрепление клиента за backend;
- ICMP health-check и исключение недоступных серверов;
- общие профили для нескольких нод;
- история версий, клонирование и откат профиля;
- автоматические версии профилей `v1`, `v2`, `v3` или собственные версии из английских букв, цифр, точек и дефисов;
- журнал событий с фильтрами по нодам, профилям и ошибкам; записи хранятся не более 14 дней;
- отдельный токен для каждой удалённой ноды;
- статистика соединений, пакетов и трафика;
- минутная телеметрия нод: RAM, CPU, load average, сеть и активные IP;
- подтверждённое удаление ноды с очисткой IPVS и остановкой агента;
- автономное обновление уже подключённой ноды при временно недоступной панели;
- обновление без удаления базы и настроек;
- перенос конфигурации со старого Ezhik UDP;
- четыре графика нагрузки на Обзоре (сеть, CPU, RAM, активные IP) за 24 часа, по всем нодам или по одной;
- диагностика ноды (доступность IPVS, готовность firewall-цепочек) в карточке ноды;
- обновление ноды до версии панели одной кнопкой с проверкой SHA-256 официального релиза.

## Требования

- Debian или Ubuntu `amd64`;
- права `sudo` или `root`;
- доступ ноды к отдельному API панели;
- открытые TCP/UDP-порты, используемые для балансировки.

## Установка одной командой

Команда одинакова для панели и ноды. После запуска установщик сам предложит выбрать вариант:

```bash
sudo apt-get update && sudo apt-get install -y ca-certificates curl && ezhik_version=0.1.0-beta.3.5 && ezhik_tmp=$(mktemp -d) && cd "$ezhik_tmp" && curl -fLO "https://github.com/ezhikdev/ezhiklb/releases/download/v${ezhik_version}/ezhiklb_${ezhik_version}_linux_amd64.tar.gz" && curl -fLO "https://github.com/ezhikdev/ezhiklb/releases/download/v${ezhik_version}/ezhiklb_${ezhik_version}_linux_amd64.tar.gz.sha256" && sha256sum -c "ezhiklb_${ezhik_version}_linux_amd64.tar.gz.sha256" && tar -xzf "ezhiklb_${ezhik_version}_linux_amd64.tar.gz" && sudo ./install.sh && cd / && rm -rf -- "$ezhik_tmp"
```

> Команда заработает после публикации тега `v0.1.0-beta.3.5`. Ошибка `404` означает, что архив pre-release ещё не собран.

Меню установщика:

```text
1) Панель
2) Нода
3) Панель + локальная нода
```

- **Панель** — web-интерфейс на порту `8080` и отдельный API нод на `8081`.
- **Нода** — агент IPVS. При первой установке готовая команда из панели уже передаёт адрес API, ID и токен.
- **Панель + локальная нода** — оба компонента на одном VPS.

Повторный запуск этой же команды обновляет установленную версию. Настройки и база сохраняются, а перед обновлением создаётся резервная копия. Нода автоматически использует сохранённые адрес API, ID и токен — повторно вводить или создавать их не требуется. Для обычного обновления уже подключённой ноды доступность панели не обязательна: агент продолжит подключение в фоне.

### Если панель временно недоступна

Ноды продолжают пропускать трафик по последней успешно применённой конфигурации. Агент периодически повторяет подключение к панели, но отсутствие связи не удаляет IPVS-правила и не останавливает трафик. Начиная с `beta.2`, агент сохраняет применённое состояние локально и восстанавливает его после перезагрузки VPS, даже если панель в этот момент недоступна. Новые изменения профилей применятся после восстановления связи.

## Как открыть панель

При установке выберите один из режимов:

1. **Только локально** — безопасный доступ через SSH-туннель.
2. **По сети** — открывает сам web-интерфейс на внешнем адресе.

SSH-туннель создаётся **на вашем компьютере**:

```bash
ssh -L 8080:127.0.0.1:8080 root@IP_ПАНЕЛИ
```

После этого откройте <http://127.0.0.1:8080>.

При сетевом режиме откройте `http://IP_ПАНЕЛИ:8080`. Для удалённых нод откройте TCP-порт `8081`. Оба порта можно изменить в разделе **Настройки**; после сохранения панель перезапустится и браузер перейдёт на новый адрес.

Посмотреть токен администратора:

```bash
sudo sed -n 's/^EZHIKLB_ADMIN_TOKEN=//p' /etc/ezhiklb/ezhiklb.env
```

## Как добавить удалённую ноду

1. Откройте **Ноды → Добавить ноду**.
2. Введите название, например `server-1`, и нажмите **Далее**.
3. Проверьте адрес API нод, обычно `http://IP_ПАНЕЛИ:8081`, и скопируйте готовую команду.
4. Вставьте команду одной строкой на новой VPS.

Команда сама установит зависимости и агент, проверит checksum, передаст ID и токен, подключит ноду и применит назначенный профиль.

Окно само покажет ожидание heartbeat, а после подключения — зелёную галочку. В списке появятся автоматически определённый IPv4, uptime связи, последняя активность и этап применения профиля.

### HTTP и HTTPS

Поддерживаются оба режима:

- для адреса `http://` панель сама добавит в команду `EZHIKLB_ALLOW_INSECURE=1`;
- для адреса `https://` нода будет использовать защищённое соединение.

HTTP подходит для тестов, VPN и доверенных сетей. Через публичный интернет рекомендуется HTTPS, потому что HTTP не шифрует токен ноды.

`127.0.0.1` из SSH-туннеля недоступен с другой VPS. Для ноды укажите публичный IP, приватный сетевой адрес или домен панели.

## Первая настройка

1. Откройте **Профили** и выберите профиль.
2. Добавьте запись, входной адрес и порт.
3. Выберите TCP, UDP или оба протокола.
4. Добавьте backend-серверы и их веса.
5. При необходимости включите Affinity и ICMP health-check.
6. Сохраните запись и опубликуйте ревизию.
7. Назначьте профиль нужным нодам.

Веса `1 + 1` распределяют трафик примерно `50% / 50%`, а `2 + 1` — примерно `66% / 33%`.

Для VPN рекомендуем начать с Affinity **3 часа**: после паузы UDP-трафик вернётся на тот же backend.

ICMP health-check проверяет доступность IP сервера, но не работу конкретного TCP- или UDP-порта.

## Полезные команды

```bash
# Версия
sudo cat /etc/ezhiklb/version

# Состояние служб
sudo systemctl status ezhiklb ezhiklb-agent --no-pager -l

# Последние логи
sudo journalctl -u ezhiklb -u ezhiklb-agent -n 100 --no-pager -l

# Логи в реальном времени
sudo journalctl -u ezhiklb -u ezhiklb-agent -f

# Проверка панели
curl -fsS http://127.0.0.1:8080/healthz && echo

# Проверка отдельного API нод
curl -fsS http://127.0.0.1:8081/healthz && echo

# Состояние агента
sudo cat /var/lib/ezhiklb-agent/state.json

# Конфигурация и статистика IPVS
sudo ipvsadm -Ln
sudo ipvsadm -Ln --stats
sudo ipvsadm -Lnc

# Перезапуск
sudo systemctl restart ezhiklb ezhiklb-agent

# Ручная резервная копия
sudo tar --ignore-failed-read -czf "/root/ezhiklb-backup-$(date +%Y%m%d-%H%M%S).tar.gz" /etc/ezhiklb /var/lib/ezhiklb /var/lib/ezhiklb-agent
```

Автоматические копии перед обновлением находятся в `/var/backups/ezhiklb`.

## Проверка `beta.3.5` на двух VPS

На первой VPS установите **Панель** или **Панель + локальная нода** и выберите сетевой доступ. Затем создайте ноду в панели и выполните полученную команду на второй VPS.

После установки ноды пришлите результат одной команды:

```bash
sudo systemctl status ezhiklb-agent --no-pager -l && sudo journalctl -u ezhiklb-agent -n 100 --no-pager -l && sudo cat /var/lib/ezhiklb-agent/state.json && sudo ipvsadm -Ln
```

Проверяем:

- статус `online`;
- совпадение `desired` и `actual`;
- отсутствие `apply error`;
- появление сервисов в IPVS;
- применение новой ревизии профиля;
- восстановление агента после перезагрузки VPS;
- обновление агента при временно выключенной панели;
- появление RAM, CPU, сети и активных IP после двух heartbeat;
- удаление удалённой ноды с очисткой её IPVS-маршрутов и отключением агента;
- обновление ноды одной кнопкой из панели, оранжевую шкалу реального прогресса (скачивание →
  проверка → установка → перезапуск) и уведомление именно по факту завершения, а не по факту
  отправки запроса;
- статус IPVS и firewall-цепочек в карточке диагностики ноды.

## Публикация `beta.3.5 pre-release`

Сначала загрузите изменённые файлы в `main`, затем создайте тег **обязательно с буквой `v`**:

```bash
git tag v0.1.0-beta.3.5 && git push origin v0.1.0-beta.3.5
```

Правильный тег автоматически создаст GitHub Pre-release и два файла:

```text
ezhiklb_0.1.0-beta.3.5_linux_amd64.tar.gz
ezhiklb_0.1.0-beta.3.5_linux_amd64.tar.gz.sha256
```

Тег `0.1.0-beta.3.5` без `v` workflow не запускает.

### Важно об обновлении ноды одной кнопкой

Кнопка «Обновить» появляется, когда `agent_version` ноды отличается от версии панели. Она работает по правилам pull-обновления: **агент сам скачивает релиз, проверяет SHA-256 и заменяет только свой бинарник**. В версиях `beta.3`–`beta.3.2` валидатор отклонял имена beta-релизов, а unit до `beta.3.5` не разрешал атомарную запись в каталог бинарника при `ProtectSystem=strict`.

Для уже установленной `beta.3.3` или `beta.3.4` достаточно один раз разрешить каталог обновления и перезапустить агент:

```bash
sudo mkdir -p /etc/systemd/system/ezhiklb-agent.service.d && printf '[Service]\nReadWritePaths=/opt/ezhiklb/bin\n' | sudo tee /etc/systemd/system/ezhiklb-agent.service.d/self-update.conf >/dev/null && sudo systemctl daemon-reload && sudo systemctl restart ezhiklb-agent
```

После перехода на `beta.3.5` этот параметр входит в штатный unit новых установок и обновлений.

## Статус проекта

`beta.3.5` — сохраняет исправление непрерывного ICMP health-check из `beta.3.4` и исправляет права systemd для атомарного self-update агента. Для уже установленной `beta.3.3`/`beta.3.4` перед первым успешным обновлением требуется один раз обновить unit обычным установщиком либо добавить временный systemd drop-in.
